## Как всё устроено

```
web/index.html (приложение товарища, Leaflet) + vendor/protomaps-leaflet.js + maps.js (подложки)
   + app.js (весь интерфейс 3.0: режимы, карта сети, нанесение, обмен, офлайн-карта)
   ├─ телефон: android/ — WebView, страница из assets, мосты AndroidBridge и KartaFiles
   └─ компьютер: run.py (127.0.0.1) подставляет pc.js (после leaflet.js), окно Edge/Chrome --app
```

- **`web/`** — ассеты из APK товарища: `index.html`, `leaflet/`, `tiles/` (плитки OSM зум 7–11,
  1562 файла), `dem/dem.bin` (рельеф). В `index.html` изменены только `<title>Карта сети</title>`
  и подключение наших файлов перед `</body>`: `vendor/protomaps-leaflet.js`, `maps.js`, `app.js`.
  Его интерфейс (шапка, панели «Радио/ВОЛС», история, окно профиля) скрыт CSS из `app.js`; его
  функции и данные (`wf_session`, `wf_nodes`, `wf_hist`) больше не используются, но не удалены.
- **`web/app.js`** (3.0, один файл вместо `net.js`, `sheet.js`, `ui.js`, `exchange.js`, `pc-ui.js`):
  - **Режимы** «Просмотр» / «Редактирование» (`.ap-seg`); при запуске всегда «Просмотр» — ничего
    не перетаскивается, нажатие — карточка сведений. В «Редактировании» — кнопка «+» (`.ap-fab`).
  - **Одно хранилище** — `karta_net` (как в 2.x: `{v, objs: {id: {id, type: node|fiber|radio,
    f, ft, t, by}}, journal}`). Отдельного «редактора» с копией линии больше нет — отсюда и
    исправление «красной линии на старом месте» (в 2.x линия жила и в редакторе, и в сети).
  - **Линия ВОЛС**: `f.fnodes` — точки `{lat, lng, kind: опора|колодец|муфта|кросс|точка|узел,
    name, nid}`, `f.lay` — участки (`'air'` по опорам — сплошная `#e8590c`, `'ground'` в земле —
    пунктир `#6d4c41`), длина на один меньше точек; `f.dist`, `f.from/f.to` (узлы на концах),
    `f.name` + `f.autoName` (имя по узлам, пока не переименовали). Радиолиния: `f.points`, без
    расчётов. Карточка линии: протяжённость, по опорам / в земле, точки по видам.
  - **Нанесение** (`tool`): перекрестие `#apCross` в центре видимой части карты (над карточкой
    на телефоне, правее панели на ПК), кнопка «Поставить точку» `#apAddPt`; нажатие на карту тоже
    ставит точку. Узел в 28 px от перекрестия — прилипание, кнопка «Завершить на «…»», линия на
    узле заканчивается. Линия сохраняется с двух точек и дальше после каждой точки.
  - **Выделенная линия** в «Редактировании»: перетаскиваемые точки (`.ap-h`), «+» между точками.
    Узел выделен — перетаскивается, точки линий с его `nid` едут следом (`follow`).
  - **Нажатия** — свой `hitTest` (точки выделенной линии → узлы 22 px → отрезки линий 16 px на
    телефоне / 9 px на ПК), без событий самих слоёв. Долгое нажатие: `contextmenu` (правая кнопка
    на ПК) и свой таймер касания 550 мс. Меню: точка (вид, номер, прокладка участков, удалить),
    линия (вставить точку здесь, прокладка участка, продолжить, название, сведения, удалить),
    узел (изменить, ВОЛС/радиолиния отсюда, переместить, удалить).
  - **Карточка** `#apSheet`: на телефоне — снизу (до 48vh), у сведений два положения (3.0.1):
    «свёрнута» (`.peek`: название + строка `.ap-sub` — длина, опоры/земля; так открываются сведения
    об узле и линии) и «развёрнута» (нажатие или смахивание вверх). Смахивание вниз: развёрнута →
    свёрнута → спрятана, **выделение и правка остаются** (точки линии можно тянуть); снимает
    выделение только «×» или нажатие на пустую карту. Панель нанесения смахиванием не закрывается.
    Шапка на узком экране: значок скрыт, «Редактирование» → «Правка», переключатель сжимается,
    🔍 и «⋮» всегда на месте. На ПК (≥900 px) —
    панель слева 380 px. Диалоги `#apDlg` (на телефоне снизу). Меню «⋮» `#apMenu`: обмен данными,
    журнал, карта без интернета, карта из интернета (нажимает его `#online`), тёмная тема
    (нажимает его `#btnTheme`), подпись. Поиск 🔍 — список с фильтрами.
  - **Обмен** — файл `{format: 'karta-seti', kind: 'fresnel', version: 3, data: {net}}`. Загрузка:
    список «добавится / изменится (какие поля) / удалится», затем карта **заменяется целиком**
    (журналы объединяются); прежняя — в `karta_prev`, «Вернуть карту». Файлы 2.x без `net`
    отклоняются. Мост Android тот же (`shareText`, `saveText`→`__kartaSaved`, `openFile`→
    `__kartaOpened`+`takeOpened*`, `locate`→`__kartaGeo`).
  - **Настройки (3.1)** — «⋮» → «Настройки», хранятся в `karta_set` (на устройстве, в файл обмена
    не попадают): тема (светлая / тёмная / как в системе), размер кнопок и текста (0.9–1.3: все px
    в правилах интерфейса умножаются функцией `cssText`, правила объектов карты `MAPRULE` — нет),
    приглушение карты в тёмной теме, подписи узлов и линий (всегда / вблизи / нет), размер значков,
    толщина линий, опоры и колодцы на карте, линейка, кнопки масштаба (телефон), карта из
    интернета, режим при запуске (просмотр / правка / как в прошлый раз, `karta_mode`), точки
    нажатием на карту (можно выключить — только перекрестие), длительность долгого нажатия,
    вибрация, формат координат точек (СК-42 / градусы / оба), на ПК — ширина панели (`--pw`) и
    строка координат; «Сбросить настройки». Описание — массив `SETTINGS`, применение —
    `applySettings()`.
  - **«Отменить»** (3.1): кнопка ↶ над кнопками карты в правке и Ctrl+Z на ПК — до 30 шагов
    (`undoStack` в `save()`, правки с паузой меньше 0,25 с — один шаг). «Обозначения» в меню.
    Свёрнутая карточка в правке — строка главных действий (`.ap-quick`: «+ ВОЛС», «+ Радио»,
    «Изменить» / «Продолжить», «Название», «Подробнее»). Подсказка на пустой карте `#apHint`.
    Карта открывается там, где её оставили (`karta_view`), в первый раз — вся сеть. Удалили узел —
    концы линий отвязываются. У радиолинии нет «+» и вставки точек (всегда две точки). Двойное
    касание при нанесении — одна точка. `window.__kartaBack()` — кнопка «назад» телефона закрывает
    окно / меню / нанесение / карточку, иначе приложение сворачивается (`moveTaskToBack`).
    В тёмной теме офлайн-карта рисуется в тёмных цветах (`KartaMap.retheme`, слой `.karta-vec`).
  - Значки узлов — формы по виду (кружок, квадрат, ромб, треугольник БС, прямоугольник,
    маленький кружок, шестиугольник), цвет — состояние. `window.KartaNet`, `window.KartaApp` — для
    проверок.
- **`web/maps.js`** — подложки: масштаб 3–19, «Схема» = OSM из интернета, «Спутник», «Гибрид»
  (Esri + подписи Яндекса), выбор в `karta_map`, подпись источника, подмена недостающей плитки
  мельче (`_tileOnError`, clip-path), Esri с `?blankTile=false`. **Офлайн-карта районов (3.0)**:
  если есть файл, под всеми подложками лежит векторный слой `protomapsL.leafletLayer` (вместо
  вшитой карты 7–11); без связи (`!online` или `navigator.onLine === false`) «Схема» рисуется
  только из него. Источник PMTiles подменён (`src.p.source`): телефон — `KartaFiles.mapBytes(o,l)`
  (base64), ПК — `/api/mapbytes?o=&l=`. CSS: у его `canvas` рамка и скругление (для профиля) —
  у плиток убраны, иначе сетка по краям плиток. `window.KartaMap = {info, reload}`.
- **Офлайн-карта** — файл PMTiles v3 с векторными плитками Protomaps (данные OSM, ODbL, масштаб
  0–15). `run.py` (`OfflineMap`) вырезает районы из суточной сборки всей Земли
  (`build.protomaps.com/ГГГГММДД.pmtiles`, список — `build-metadata.protomaps.dev/builds.json`)
  запросами Range: каталог → нужные плитки → новый файл (корень ≤ 16 КБ, листовые каталоги,
  одинаковые плитки один раз). Районы — прямоугольники в `OfflineMap.REGIONS`; по умолчанию
  Херсонская и Запорожская (189 МБ, сборка 20261113), Крым ~90 МБ, Ставрополье ~175 МБ.
  ПК: файл `map/karta-offline.pmtiles` (+ `.json` с районами), API `GET/POST /api/map`
  (состояние / скачать), `/api/mapbytes`; без окна: `python run.py --offline-map [районы]
  --map-file путь`. Телефон: файл импортируется (`readUri` узнаёт `PMTiles` по первым байтам) в
  `files/karta-offline.pmtiles`, мост `mapSize/mapDate/mapBytes/mapDelete`, ответ
  `__kartaMap(ok, msg)`, ход `__kartaMapProgress(МБ)`. Библиотека `web/vendor/protomaps-leaflet.js`
  5.1.0 (BSD-3, лицензия рядом). Плитки OSM/Esri/Яндекса массово не скачиваются (запрещено
  их условиями) — для этого и векторная сборка.
- **Запас плиток** (как в 2.3–2.8): телефон — `TileCache.java` (`files/tilecache`, 30 дней,
  500 МБ), ПК — `run.py` `TileCache` (`data/tilecache`, 1 ГБ, `/tc/<osm|sat|skl>/z/x/y`), в
  интернет только при `wf_online`. На ПК плитки через `t1…t4.localhost`, `?v=<версия>`.
- **Старая копия программы** (2.8): новая просит старую закрыться (`/api/info`, `POST /api/quit`
  с `X-Karta: quit`), иначе на Windows завершает процесс на порту; `pc.js` показывает красную

- **`web/pc.js`** — только для ПК, после `leaflet.js`: localStorage (`wf_*`, `karta_*`) ↔

- **`run.py`** (3.0) — только стандартная библиотека. 127.0.0.1:8790, проверка `Host`/`Origin`.
  `/api/state`, `/api/elev`, `/api/info`, `/api/quit`, `/api/map`, `/api/mapbytes`. Резервные копии

- **`android/`** — пакет `ru.netmap.app`. `MainActivity.java` — оболочка товарища (WebView,

### Формат dem.bin

`"DE"` + 2 байта, `uint16` число квадратов; квадрат: `int16` широта, `int16` долгота, `uint16 n`,
затем `n×n` `int16` (little-endian), строки с севера. Билинейно: `r = (lat0 + 1 − lat)·(n − 1)`,
`c = (lon − lon0)·(n − 1)`.

## Принятые решения и почему

- **Страница товарища не трогается.** Всё новое — в отдельных файлах (`exchange.js`, `pc.js`),
  чтобы его обновления можно было переносить простой заменой `index.html` (и вернуть две строки).
- **ПК-версия — та же страница**, а не переписанная: сервер подставляет `pc.js`, который заменяет
  мост Android. Данные — в файле на диске, а не в localStorage браузера, чтобы не пропадали при
  чистке браузера и попадали в резервные копии.
- **Сервер только на 127.0.0.1**, проверка `Host`/`Origin` от чужих страниц в браузере.
- **Сеть при импорте объединяется** (для каждого поля — более поздняя правка, удаление — поле
  `deleted`), повторная загрузка файла ничего не меняет. **Текущая работа** (точки радиолинии и
  паспорт) заменяется только с флажком; флажок включён, если в файле нет сети (старые файлы).
  История профилей дополняется. Ошибочная загрузка отменяется «Вернуть как было» (снимок и сети).
- **Доработки — отдельными файлами** (`net.js` и др.), приложение товарища меняется минимально:
  его функции подменяются через `window`, его панели дополняются через DOM.
- **На рабочий стол плитки идут архивом `web/tiles.zip`**: передача на ПК ограничена 50 файлами за
  раз. `run.py` читает и папку, и архив. `*.zip` в `.gitignore`.
- **Ключ подписи APK** в репозиторий не кладётся (репозиторий публичный). Сборка берёт его из
  секрета GitHub `KEYSTORE_B64` (PKCS12, псевдоним `netmap`, пароль в `android/app/build.gradle`).
  Копия у заказчика: `Desktop\Карта сети\data\ключ подписи APK\`. Потерять нельзя. Первый ключ
  (до 12.11.2026) остался в истории репозитория и считается раскрытым.
- **targetSdk 34**, а не 35: с 35 Android рисует приложение под системными панелями.
- **3.0: расчёты убраны** (заказчик: «вообще убери эти функции, оставь только протяжённость»):
  профиль, бюджет, подбор оборудования, паспорт и расчёт кабеля скрыты. Взамен — прокладка по
  участкам «по опорам / в земле», видно на карте.
- **3.0: загрузка файла заменяет карту целиком** (заказчик: «моя карта полностью обновляется, не
  остаётся старых точек»), а не объединяет, как в 2.2–2.8. Перед загрузкой — список изменений.
- **3.0: всё в одном хранилище `karta_net`**, без отдельного редактора — двойников линий нет.
- **Офлайн-карта — векторная сборка Protomaps**, а не скачивание плиток-картинок: OSM, Esri и
  Яндекс запрещают массовое скачивание, а данные OSM (ODbL) можно брать целиком.

## Договорённости с заказчиком

- Программы поставляются папкой на рабочем столе, не архивом. Папка проекта: `Desktop\Карта сети`.
- Изменения отправляются в GitHub и одновременно кладутся в папку на рабочем столе. После каждого
  push сверять размеры файлов в папке на рабочем столе с репозиторием.
- Писать в `.git` на компьютере заказчика Claude не может, поэтому папку с репозиторием связывает
  bat-файл `GitHub - подключить и обновить.bat` (нужен Git for Windows).
- Создавать репозитории Claude не может: заказчик создаёт пустой репозиторий и даёт к нему доступ.
- Папка `data/` в репозиторий не попадает.
- Картинки (PNG, SVG) при передаче на компьютер заказчика получают метаданные C2PA, файл меняется.
  В репозиторий кладётся вариант, который попал на рабочий стол.
- Файлы в `.github/` Claude в папку на рабочем столе положить не может, их восстанавливает
  bat-файл через `git checkout -- .github`.
- Удалять файлы на компьютере заказчика Claude не может без разрешения — лишнее перечисляется ему.
