# Карта сети — файл проекта

Этот файл — память проекта. Читать его в начале каждой сессии и **дописывать после каждого
изменения**: что сделано, какие решения приняты и почему, что осталось. Писать по-русски.

## Что мы делаем

Заказчик — Дима, работает в транспортной сети связи. В сети много узлов доступа, их постоянно
обслуживают несколько бригад. Нужно приложение, где на карте наносятся узлы доступа и линии между
ними, и у всех пользователей это обновляется в реальном времени.

Требования (со слов заказчика):

- приложение на Android в виде APK;
- сервер у них на компьютере (Windows), несколько пользователей;
- телефоны подключаются не из закрытой сети, а через мобильный интернет оператора, местами Wi-Fi;
  сервер подключён к интернету;
- репозиторий на GitHub (`Almazny26/apk_map`) и папка на рабочем столе, синхронизированная с ним;
- этот файл в репозитории, где записано всё, что мы делаем;
- в остальном полная свобода действий.

## Как всё устроено

```
телефон (APK)  ─┐                       ┌─ SQLite: data/netmap.db
браузер на ПК  ─┼─ HTTP(S) + SSE ─ сервер (Python) ─ журнал, резервные копии
телефон (APK)  ─┘
```

- **Сервер** — `run.py` + `core/`, только стандартная библиотека Python 3.8+. У заказчика стоит
  Python 3.14, остальные его программы (SwitchPanel, Мониторинг66) тоже на Python и запускаются
  bat-файлом из папки на рабочем столе — здесь так же.
  - `core/store.py` — SQLite: пользователи, сессии, объекты (узлы и линии), журнал, справочники.
  - `core/app.py` — HTTP API, поток событий (Server-Sent Events), раздача `web/` и `apk/`.
  - `run.py` — запуск, настройки (`data/config.json`), первый администратор, резервные копии.
- **Клиент** — `web/`, чистый JavaScript без сборки, карта на Leaflet 1.9.3 (лежит в
  `web/vendor/leaflet`). Один и тот же клиент раздаёт сервер (для браузера) и он же вшит в APK.
  - `js/core.js` — хранение на устройстве, запросы, синхронизация.
  - `js/mapview.js` — карта: подложка, узлы, линии, подписи, геолокация.
  - `js/ui.js` — карточки, формы, списки, режимы (постановка узла, выбор узлов, трасса), вход.
- **Android** — `android/`, оболочка на WebView без внешних библиотек (`MainActivity.java`).
  Клиент берётся из `web/` при сборке (`assets.srcDirs`). Оболочка даёт: хранение данных в файлах
  приложения (мост `NetMapNative`), кэш плиток карты на диске, разрешение на геолокацию.
- **Сборка APK** — GitHub Actions, `.github/workflows/build-apk.yml`: собирает APK и кладёт его в
  `apk/karta-seti.apk` + `apk/version.json` отдельным коммитом. Сервер раздаёт APK по адресу
  `/apk/karta-seti.apk`, приложение по `version.json` узнаёт о новой версии.

### Синхронизация (главное в проекте)

- У каждого объекта есть `rev` — номер последнего изменения. Номер сквозной, это первичный ключ
  таблицы `journal`.
- Клиент хранит `base` (что прислал сервер), `queue` (свои неотправленные правки) и показывает
  `view` = `base` + `queue`. Правка сразу видна на экране и лежит в очереди, пока сервер её не
  подтвердит. Поэтому приложение работает без связи.
- Правка — это изменение отдельных полей (`patch`), а не объект целиком. Двое поменяли разные
  поля одного узла — сохраняются обе правки. Одно поле — побеждает пришедшая последней, в журнале
  остаются обе.
- У правки есть `op_id`. Сервер запоминает применённые `op_id`, повторная отправка после обрыва
  ничего не меняет.
- Сервер рассылает изменения через SSE (`/api/events`). При подключении клиент догоняет
  пропущенное через `/api/changes?since=rev`. Применение правок и рассылка идут под одной
  блокировкой (`App.ops_lock`), чтобы события приходили строго по порядку ревизий.
- Удалённые объекты остаются в базе с `deleted=1`, чтобы клиенты узнали об удалении. Удаление узла
  удаляет и его линии. Правка удалённого объекта отклоняется с кодом `deleted`.

### API

`GET /api/info`, `POST /api/login`, `POST /api/logout`, `GET /api/me`, `POST /api/password`,
`GET /api/snapshot`, `GET /api/changes?since=`, `POST /api/ops`, `GET /api/events` (SSE),
`GET /api/journal`, `PUT /api/settings`, `GET|POST /api/users`, `PATCH /api/users/<id>`.
Токен — в заголовке `Authorization: Bearer`, для SSE — в параметре `token`.

## Принятые решения и почему

- **SSE, а не WebSocket.** В стандартной библиотеке Python нет WebSocket-сервера, а ставить пакеты
  на рабочий ПК заказчика не хочется. SSE — обычный HTTP-ответ, хорошо проходит мобильные сети.
- **Обычный HTTP(S) без VPN.** У мобильных операторов в России WireGuard и OpenVPN режутся
  фильтрацией, поэтому сервер открыт наружу по белому IP и порту 8790. HTTPS поддержан
  (`https_cert`, `https_key` в `data/config.json`), но по умолчанию выключен: нужен домен и
  сертификат.
- **Офлайн-режим обязателен.** Мобильный интернет в регионах периодически отключают, остаются
  только «белые списки», куда сервер заказчика не попадёт. Wi-Fi при этом работает.
- **Клиент в APK открывается из assets (`file://`)**, а не с сервера: приложение запускается без
  связи. Минус: чтобы обновить клиент на телефонах, нужен новый APK.
- **Данные на телефоне хранятся через мост в файлах приложения**, а не в IndexedDB/localStorage:
  нет ограничения по размеру и нет сомнений, как они ведут себя на `file://`. В браузере —
  localStorage.
- **Плитки карты кэширует оболочка** (перехват запросов с меткой `nmcache=1`), 90 дней.
- **Линия ведётся по точкам с перекрестием в центре экрана** (режим `draw` в `ui.js`): пальцем
  точно в поворот улицы не попасть, а подвести карту под перекрестие легко. Перекрестие
  «прилипает» к узлу в радиусе 30 px — так линия завершается.
- **Точки трассы в редакторе — перетаскиваемые DOM-маркеры** (`M.editPath` в `mapview.js`), а не
  фигуры на canvas: их можно тянуть пальцем. Между точками стоят «средние» точки, которые при
  перетаскивании превращаются в новый изгиб.
- **Свои окна подтверждения** (`U.confirm`) вместо системных `confirm()`.
- **targetSdk 34**, а не 35: с 35 Android рисует приложение под системными панелями.
- **Узлы и линии рисуются на одном canvas** (тысячи объектов без тормозов). При нажатии Leaflet
  выбирает объект, нарисованный последним, поэтому после отрисовки линий узлы поднимаются наверх
  (`restack` в `mapview.js`).
- **Ключ подписи APK** в репозиторий не кладётся (репозиторий публичный). Сборка берёт его из
  секрета GitHub `KEYSTORE_B64` (base64 от файла PKCS12, псевдоним `netmap`, пароль в
  `android/app/build.gradle`). Без секрета сборка проверочная: временный ключ, APK в `apk/` не
  публикуется. Копия ключа лежит у заказчика: `Desktop\Карта сети\data\ключ подписи APK\`.
  Потерять ключ нельзя: без него обновления не встанут поверх установленного приложения.
  Первый ключ (до 12.11.2026) остался в истории репозитория и считается раскрытым, им ничего
  не подписывалось и не раздавалось. Старый файл `android\netmap.keystore` в папке на рабочем
  столе не используется.

## Договорённости с заказчиком

- Программы поставляются папкой на рабочем столе, не архивом. Папка проекта: `Desktop\Карта сети`.
- Изменения отправляются в GitHub и одновременно кладутся в папку на рабочем столе.
- Писать в `.git` на компьютере заказчика Claude не может, поэтому папку с репозиторием связывает
  bat-файл `GitHub - подключить и обновить.bat` (нужен Git for Windows).
- Создавать репозитории Claude не может: заказчик создаёт пустой репозиторий и даёт к нему доступ
  приложению Claude в GitHub.
- Папки `data/` и `data-demo/` (база, пароли, журнал) в репозиторий не попадают.
- Картинки (PNG, SVG) при передаче на компьютер заказчика получают служебные метаданные о
  происхождении (C2PA), файл от этого меняется. Чтобы git в папке на рабочем столе не видел
  расхождений, в репозиторий кладётся именно тот вариант картинки, который попал на рабочий стол
  (брать из `/mnt/user-data/outputs/...` после копирования туда).
- Файлы в `.github/` Claude в папку на рабочем столе положить не может (защищённое место), их
  восстанавливает bat-файл через `git checkout -- .github`.

## Как проверять

- Сервер: `python -m unittest discover -s tests -v` (12 тестов, идут около 20 секунд).
- Клиент: `python run.py --demo --port 8791`, вход `admin` / `demo-admin`.
- APK собирается только в GitHub Actions; в песочнице Claude нет Android SDK и нет доступа к
  серверам Google и Maven.
